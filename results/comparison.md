# Core Comparison

Regenerated by `make results`. Every core is measured on identical stimulus
with the same pinned toolchain, so the rows are directly comparable.


| Core | IPC | Fmax (MHz) | LUT / FF / BRAM / DSP | MIPS |
|---|---|---|---|---|
| RV32I single-cycle | 1.000 | 216.7 | 2123 / 1438 / 0 / 0 | 216.7 |
| RV32I 5-stage pipeline | 0.612 | 259.0 | 2718 / 2446 / 0 / 0 | 158.5 |
| RV32I pipeline + L1 I$/D$ (4 KiB each) | - | 214.4 | 5740 / 3654 / 10 / 0 | - |

**IPC alone is misleading.** A single-cycle datapath retires one instruction per
clock, but one clock period must then contain fetch, decode, execute, memory and
writeback - so it buys its IPC with a slow clock. Real throughput is
`IPC x Fmax`, which is why both are recorded and why the MIPS column exists.

**These IPC figures assume ideal memory.** That is the one case where the
pipeline's prefetch buffer is pure overhead; under any real memory latency the
ranking flips (see results/experiments.md). The MIPS column is therefore a
lower bound for the pipeline, not its real-world throughput.

**MIPS is only comparable within one ISA.** It counts instructions, not work.
An RV32I core scores far higher MIPS than an RV32IM core on the same C source
purely because it executes far more instructions to compute the same answer -
libgcc replaces one `div` with dozens of shift-and-subtract steps. Compare wall
clock on identical source, never MIPS across different instruction sets.

**Fmax is derived from slack:** `Fmax = 1 / (target - WNS)`. Synthesis fails
outright if the timing report shows any combinational loop, because Vivado
would otherwise cut the loop arbitrarily and the number would mean nothing.
These are post-synthesis estimates, not placed-and-routed results.

**The single-cycle Fmax is optimistic in a way the pipeline's is not.**
`magic_mem` is excluded from synthesis, so instruction fetch and data access sit
outside every measured path. A single-cycle core genuinely cannot do that - it
must fit both memory accesses inside one clock period - whereas a pipeline
already isolates them in their own stages. The gap between these two rows is
therefore understated, not exaggerated.

**Cycle-count CSRs cannot be compared against an ISS.** Spike is instruction
accurate, not cycle accurate, so any test reading mcycle/cycle will legitimately
disagree with RTL once IPC differs from 1. This matters more from Phase 2 on.
